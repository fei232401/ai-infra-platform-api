# AI Infra Platform · Control Plane API

推理平台的控制层后端。

它回答三个问题：**有哪些推理后端可用**、**请求该走哪一条路**、**每个请求实际发生了什么**。

## 为什么需要这一层

现有调度器把两样东西放在了错误的地方：

| 东西 | 现在在哪 | 后果 |
|------|----------|------|
| 后端清单 | 一份 YAML 文件 | 增删一个后端要改文件、重启进程 |
| 后端评分与会话映射 | 进程内存 | 重启即丢失，滚动窗口从头再来 |

控制层把这两样从"进程内的临时状态"变成"服务里的持久状态"：后端清单可动态变更，评分与会话映射落库后可跨重启复用。

一句话：**调度器负责做决策，控制层负责让决策有据可依、有迹可查。**

## 它不做什么

- **不做推理**：推理在后端引擎（Ollama / vLLM）里
- **不做路由决策**：决策算法属于调度器。本服务只负责把决策所需的输入准备好、把决策结果记下来
- **不做最终认证裁决**：接入层负责快路径校验（签名与过期），本服务负责慢路径查询（密钥状态与用量）
- **不直接对外**：所有流量必须经接入层进入

## 目录

```
src/
  api/          HTTP 路由层。只做参数解析与响应组装，不含业务判断
  service/      业务逻辑。不依赖任何 Web 框架，可被单独测试
  repository/   数据访问。唯一与数据库打交道的地方
  domain/       领域模型与类型定义
tests/
docs/           设计与决策记录
```

**依赖方向只向下**：`api → service → repository → domain`。

出现反向引用（例如 repository 去调用 service）一律视为设计错误，不是风格问题。

## 与其它仓库的关系

| 仓库 | 关系 |
|------|------|
| `ai-infra-platform-db` | 提供 schema 契约。本仓库只读用，不定义任何表 |
| `ai-infra-platform-web` | 本仓库提供 HTTP 接口，前端消费 |
| `elastic-scheduler-v2` | 本仓库为其提供后端清单与持久化状态 |
